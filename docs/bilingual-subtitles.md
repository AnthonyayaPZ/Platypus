# 中英双语字幕导入

手动上传 SRT / VTT 时，服务端先按字幕行识别英文和中文，再构建学习内容。

- 同一字幕块内支持英文在上、中文在上、多行英文和 HTML `<br>` 换行。
- 支持英文后以句末标点或 ` / `、` | ` 分隔的同行中文译文。
- 中英文各占一个字幕块时，仅在起止时间完全相同时配对；不会按相邻顺序猜配。
- 中文行中的英文名称保留在中文里，不提取为新的英文字幕。
- 完整双语字幕无需翻译或语义切分 API，解析后直接进入可学习状态。
- 上传时有“重新分句”开关，默认开启。开启时英文单语沿用阅读切分；双语仅在英文句子数与中文句子数一致时本地按句配对，否则保留原块。关闭时英文单语及双语均完整保留原字幕块，不合并、不重新分句。
- 部分字幕缺少中文时，仅补译缺失部分。失败重试保留导入的中文和已成功翻译内容。
- 纯中文字幕不能用于英文学习；没有配对的纯中文块不作为英文发送给模型。

## 配对与长段落

已有译文不会按单词数或中文字符数强拆。仅在开启重新分句、两种语言的句子边界数量匹配时做本地按句配对，其他情况保留原块。特别长的双语块仍可能较高，建议源文件按自然语义提前制作成较短的双语块。关闭开关后，`preserveCueBreaks` 随句子持久化，后续读取、阅读升级、翻译重试均不会覆盖用户选择。

英文单语字幕继续使用已有阅读切分、语义辅助及批量翻译流程。文件大小、3 小时时长、时间轴及段落数量限制继续生效。

## 客户端与发布

双语识别属于服务端处理，旧客户端也能直接使用原译文。重新分句开关已添加到 Web 与安卓上传界面，安卓需要安装新版 APK 才能手动关闭；旧客户端不传选项时默认开启。内部标记保存在现有 JSON 句子字段中，无需为此新增数据库字段。

本次发布同时包含此前本地完成的处理进度功能及其增量迁移 `0004_subtitle_progress.sql`。已有导入内容不会自动重新解析，需要重新上传双语源文件才能利用原有译文。不同的重新分句选项对应独立的导入任务，原历史文章不受影响。

## 自动化验证

`tests/bilingual-subtitles.test.ts` 覆盖语言顺序、换行、标签、同行分隔、精确时间配对、长块配对及纯中文输入。`tests/video-study-server.test.ts` 通过数据库与真实工作任务流程验证：完整双语零 API 调用，混合字幕仅补译缺失部分，重试不覆盖导入译文。
