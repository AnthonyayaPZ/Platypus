## 目标与当前约束

- 在手机上输入 YouTube 标题，选择正确的视频，获取英文字幕并逐句展示中文翻译。
- 英文句子保留原始顺序；每个可学习的单词呈现为可点击的矩形词块。
- 点击词块只加入待收藏区，不自动调用词典 LLM、不自动收藏。
- 在当前页面查看、修改、删除待收藏词，选择已有词库，再手动提交。
- 生成词条时复用现有“公共词典缓存优先，未命中才调用 LLM，返回两组近义与两组反义对比”的规则。
- 延续个人单工作区，不增加账号体系或用户隔离。
- Android 使用原生 Compose；Web 使用现有 React 页面和同一套服务端 API。

## 两阶段交付

### 第一阶段：可交互 Demo

这一阶段先验证阅读、点词和批量收藏流程是否适合手机。

1. 新增“视频学词”入口，提供桌面、手机响应式 Web 和原生 Android 页面。
2. 两端使用同一份自编的演示字幕及中文翻译，明确标记“演示字幕”，不将样例伪装成真实 YouTube 下载结果。
3. 演示标题输入、视频候选结果、加载状态、句子词块、选中态和缓存区。
4. 实现待收藏区的持久草稿、去重、修改、删除、手动新增及目标词库选择。
5. 批量操作先使用可控的演示处理器展示等待、进行中、成功、失败和重试，不写入正式词库；界面明确标记演示结果。
6. 为下一阶段保留真实服务接入边界；首版不提供会写入正式词库的提交路径。
7. 交付 Web 可交互页面、Android Preview 和 Demo APK；演示使用明确的数据结构与独立示例素材。

### 第二阶段：真实端到端链路

1. 在服务器中接入视频搜索、字幕获取和缓存。
2. 获取英文字幕，清理滚动式自动字幕的重叠内容，合并成可阅读的句子，保留时间戳。
3. 调用服务端 LLM 分批翻译句子，按句子 ID 对齐返回；翻译失败时保留英文并允许重试。
4. 接入后台批量词条生成任务与收藏写入，提供进度查询和部分失败重试。
5. Web、Android 共同使用真实 API；演示模式仍可独立运行，便于回归验证。

阶段顺序可根据反馈调整；若要求首版直接联调，则在同一次开发中顺序完成两个阶段。

## 页面与交互

### 输入与视频确认

- 输入框支持标题；同时支持 YouTube 链接，方便精确指定视频。
- 标题检索返回少量候选，展示标题、频道、时长和缩略图；由使用者确认。
- 下载对象仅为字幕，不下载完整视频。
- 加载过程展示“查找视频 → 获取字幕 → 整理句子 → 翻译中”。
- 字幕缺失、服务不可达、翻译失败分别显示可操作的错误状态；失败时允许导入 SRT/VTT 字幕继续学习。

### 字幕阅读

每个句子包含：时间戳、按原句顺序排列的英文词块、中文翻译。

- 词块自动换行；手机上提供足够大的点击区域和明显选中态。
- 标点留在原句位置，不作为独立词汇加入待收藏区。
- 英文缩写、连字符词和撇号词保留整体；原始显示文本与提交给词典的小写词分开保存。
- 不自动把屈折词变回原形；允许在待收藏区手动修改，例如将 `running` 改成 `run`。
- 同一词出现多次时使用一致的选中态，缓存区只占一条，保留来源句。
- 提供“只显示含已选单词的句子”筛选，以及译文显示/隐藏选项。

### 待收藏区

- 手机：底部固定“待收藏 N 词”工具条，展开底部面板；关闭面板后继续阅读。
- 桌面：字幕在左侧，待收藏区在右侧固定展示。
- 支持手动新增、词形修改、删除、清空、目标词库选择及查看来源句。
- 草稿在 Web 本地存储、Android 本地持久存储；刷新或退出应用后保留。
- 更换视频不清空待收藏区；来自不同视频的词可以合并提交。
- 首版草稿只在当前设备保存，不承诺跨设备同步。

### 手动提交与进度

- 提交前显示目标词库、唯一词数量及待生成数量。
- 提交后生成固定批次快照；显示每个词的等待、生成、已收藏、失败状态。
- 同一批次限制并发，默认不超过 2 个 LLM 请求，同时限制批次大小。
- 成功词从待处理草稿移除，保留批次结果；失败词留在草稿并展示错误，支持单独重试。
- 重复提交不重复收藏；已有词条直接复用，已有收藏不覆盖笔记与复习进度。
- 收藏完成后刷新现有词库、复习计数等状态。

## 技术接入点

### 字幕服务

现有应用包含 Vinext/Cloudflare 兼容构建，而当前部署是阿里云 Docker/Node。为避免把外部可执行进程耦合进 Web 路由，真实字幕获取优先使用独立的内部字幕服务。

- 内部服务使用 yt-dlp 获取公开视频元信息及可用字幕，优先人工英文字幕，其次英文自动字幕。
- 服务只向 Compose 内网暴露；应用调用固定内部服务地址。
- 标题与 URL 使用参数化调用，不拼接 shell 命令。
- 接口只接受规范的 YouTube 视频 ID/允许的链接格式，不提供任意 URL 下载代理。
- 设置超时、字幕大小和视频长度上限，并按 videoId + 语言缓存。
- 首先验证阿里云服务器到 YouTube 的实际连通性；无字幕或访问失败时明确失败，不静默替换成演示数据。

参考：

- [yt-dlp 官方文档：字幕选项和跳过视频下载](https://github.com/yt-dlp/yt-dlp#usage-and-options)
- [YouTube 官方 captions.download 权限要求](https://developers.google.com/youtube/v3/docs/captions/download)

### LLM 与收藏

- 将 `app/api/search/route.ts` 的“检索缓存 → 生成 → 校验 → 保存词条”抽为共享服务。
- 继续复用 `lib/llm.ts` 中的词条结构与两近义/两反义校验，不重新定义较弱的生成规则。
- 将现有 `saveWord` 收藏事务抽为共享方法；批量处理不通过客户端循环模拟人工搜索。
- 翻译使用独立提示词与返回结构，只翻译句子，不允许模型改变原始英文字幕。
- 字幕文本视为待翻译数据，不作为模型指令。
- 真实长任务采用可查询进度的后台任务，不让手机维持一次长时间 HTTP 请求。

### API 草案

| 接口 | 用途 |
| --- | --- |
| `POST /api/video-study/search` | 按标题查找候选视频，或解析链接 |
| `POST /api/video-study/documents` | 发起字幕整理/翻译任务 |
| `GET /api/video-study/documents/:id` | 获取视频信息、字幕句子与翻译进度 |
| `POST /api/video-study/imports` | 提交词汇批次和目标词库 |
| `GET /api/video-study/imports/:id` | 查询每词处理与收藏进度 |
| `POST /api/video-study/imports/:id/retry` | 仅重试失败项 |

第一阶段提供同形状的演示适配器；真实适配器启用后保持页面组件和 Android DTO 稳定。

### 数据

- 继续复用 `dictionary_entries`、`word_relations`、`user_words` 和 `group_words`。
- 第一阶段不改正式数据库结构。
- 第二阶段增加字幕文档缓存、后台任务/任务项、收藏词来源关系；来源保存 videoId、标题、时间戳及原句。
- 不改变已有个人单工作区数据归属。
