# 字幕上传与处理进度（本地开发，未部署）

Web与Android 0.6.0/versionCode 9增加一个紧凑进度卡片，区分网络上传与服务端处理。不显示不可靠的预计剩余时间，也不为解析/切分等阶段编造百分比。

## 客户端

- Web使用XMLHttpRequest上传事件，安卓使用计数RequestBody，依据实际写出的请求体字节显示上传进度。100%仅表示本次上传字节已发送，仍等待服务器校验和入队响应；不是翻译完成。
- 上传断网或响应丢失时提示先查看学习记录确认是否收到，不自动重传，避免重复任务。上传阶段不承诺断点续传。
- 服务端阶段为排队、获取字幕/解析文件、切分阅读段落、翻译、完成、部分失败或失败。只有可确定总段数的翻译/终态显示百分比。
- 翻译的“已处理”计数为成功加失败；同时明确显示成功和失败数量。部分失败即使已处理100%，也不会显示为全部翻译成功。
- 活跃文章约每2秒拉取一次轻量进度；完整字幕最多约10秒按内容版本刷新一次，完成时立即刷新最终正文。旧服务没有进度接口时降级为原有完整文章拉取。
- 安卓保留原有离线文章缓存和阅读位置；进度行是否显示会同步计入恢复位置，避免新增卡片导致跳转偏移。

## 服务端与迁移

新增 `GET /api/video-study/documents/:id/progress`，返回id、状态、错误、更新时间与小型progress对象，不返回字幕正文。

progress包含stage、total、processed、succeeded、failed、updatedAt。后台在阶段切换和每个翻译批次完成时，随正文原子保存计数，服务重启后不依赖内存恢复。

迁移文件 `drizzle/0004_subtitle_progress.sql` 只向 `video_study_documents` 添加可空JSONB列，不重写旧字幕、不清零任务、不改动已有收藏或复习表。旧文档/旧worker留下的空或过时计数由接口从已保存字幕回算，直到新worker写入有效计数。

此功能最初于2026-11-10仅在本地完成，当时未应用迁移或部署。2026-11-27按用户要求与双语字幕识别、重新分句开关一起发布；迁移前已检查活跃任务并备份数据库，不重试历史字幕任务。
