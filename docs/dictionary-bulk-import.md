# 词条 JSON 与搜索页批量收藏

## 生成契约

批量输入 1–30 个已去重的英文单词，一次请求、一次响应；只对没有服务器词典缓存的词调用 LLM，不退回逐词调用。JSON Schema 见 `dictionary-response.schema.json`。单词搜索返回同样的单个词条，不加 `entries` 包装。

```json
{
  "entries": [
    {
      "word": "anthropology",
      "phonetic": "/ˌænθrəˈpɒlədʒi/",
      "part": "n.",
      "meaning": "人类学",
      "summary": "研究人类及其文化、社会与生物特征的学科。",
      "example": "She studies anthropology at university.",
      "exampleZh": "她在大学学习人类学。",
      "relations": []
    }
  ]
}
```

`relations` 必须存在，可以为空；近义、反义各自允许 0、1、2 项，不要求成对出现。有关联词时，每项为：

```json
{"word":"fragile","type":"antonym","comparison":"fragile 表示脆弱；resilient 强调承压后恢复。","usage":"形容易损坏或受挫的对象用 fragile。"}
```

关联词必须在相同义项、兼容词性和同一语义维度下成立。相关学科、上下位类别、共现词、不同物品不自动构成近义或反义。专有名词、学科名、缩写、功能词等没有自然关联词时返回 `[]`，禁止凑数、`null`、占位词或用“无”作为词条。无法确认读音时允许空字符串。实际释义、例句、比较仍必须完整。

共享提示词与示例在 `lib/llm.ts` 的 `dictionaryPrompt` / `dictionaryJsonTemplate`，同时用于单词查询和批量收藏。服务器额外验证输入/输出目标词一致、不遗漏、不重复、不互相矛盾、不把目标词作为自身关联词；`synonyms` / `antonyms` 从通过校验的 `relations` 推导，不让模型重复生成两份冲突数据。空关联组在 Web 与 Android 均不渲染。

词典请求启用 `response_format: {"type":"json_object"}`；直连 DeepSeek 时明确关闭思考，避免推理消耗词条输出预算。预算为 `max(6000, 1400 * 未缓存词数)`，最大 42000 tokens；不改变字幕翻译与语义切分设置。接口需兼容 JSON object 模式。DeepSeek 文档仅保证 JSON 语法，字段、关联词真实性仍由提示词及服务端校验共同约束，不能保证语义零错误。

截断、空响应、无效 JSON、遗漏/重复目标词、词条字段错误分别提示；日志只记录安全的问题类别与目标单词，不记录密钥、原始回答或思考内容。失败词条不会收藏，不完整 JSON 不做拼接修复。有效词条和已有学习信息保持不变。

## 搜索页交互

- 默认单词搜索框及 Web 的键盘补全逻辑不变。添加低调的“＋ 批量收藏”入口，点击才展开与原界面同色的抽屉/底部面板。
- 支持逗号、中英文分号、顿号、空格、换行分词；保留连字符和撇号，统一大小写、去重。无效词或超过 30 个时整体拒绝本次添加并保留输入，不静默丢弃。
- 只对最后一个未确认词显示补全；选择后保留前面的输入，确认成待上传标签。标签可删除后重新添加。粘贴词表后点击“添加”确认；输入未确认时禁用上传，防止漏词。
- 选择目标词库，手动“上传并收藏 N 个词”才调用批量生成。复用 `/api/video-study/imports` 与已有后台 worker，手动输入词的 `sources` 为 `[]`，无需数据库迁移。
- Web 和安卓使用独立于视频草稿的本机保存区，持久保存草稿、待提交请求编号、服务端批次编号和成功确认。网络重连复用同一编号；成功项移出草稿一次，失败项保留并支持“仅重试失败项”。上传期间锁定编辑，关闭面板不停止服务器任务。
- 安卓增加应用内常用词联想，离线使用与 Web 相同的 40000 词表，不调用 LLM。词表来自 `public/wordlists`，保留其来源说明；构建时可通过 `PLATYPUS_WORDLIST_ASSETS_DIR` 指定绝对目录。

安卓新入口需要更新 APK（0.3.0 / versionCode 4）；空关联词响应也兼容旧 APK。旧的词典缓存不会在本次更新中被重写，已收藏词、笔记、复习进度及视频词汇来源均不迁移、不清空。

## 本轮验证（2026-11-03）

- Web 生产构建、TypeScript、ESLint 通过；29 项服务端/分段/批量逻辑测试、11 项 Web 测试通过。
- Android 20 项测试通过；`lintDebug` 无错误（10 个依赖/SDK 等警告），`assembleDebug` 通过。源码中的 Gradle daemon 配置尝试下载 JDK 21 失败，因此在已有隔离验证目录使用已安装 JDK 17 完成构建；未改动项目的 JDK 设置。
- 生成 `android/app/build/outputs/apk/debug/platypus-0.3.0-debug.apk`，包名 `com.anthonyaya.platypus.debug`、versionCode 4，签名验证通过且与 0.2.1 debug 包一致，可覆盖安装。
- 本地浏览器通过隔离 API fixture 验证默认收起、粘贴去重、只补全最后一个词、单词搜索 Tab 补全、空关联卡片隐藏、部分成功、失败重试和刷新恢复；fixture 不转发任何真实 API/数据库/LLM 请求。预览使用开发服务器，本机 Windows 的生产启动静态资源访问未通过，未修改生产服务器代码绕过。
- 本地没有 LLM 凭据，本轮未进行新提示词的真实模型复测；没有推送 GitHub 或部署服务器，没有改动线上数据。当前 APK 仍使用原公网 API 地址，后台生成规则需部署新版 Web/worker 后才会生效。
