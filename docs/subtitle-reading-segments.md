# 手机字幕阅读分段（兼容旧 APK）

## 规则与排版权衡

- 短句保持原样，不为凑长度强行合并。长句以 12–18 词为优化目标，24 词为上限，长单词较多时提前切分。
- 使用整句动态规划，而不是每 N 词截断：比较标点、分句连接词、字幕真实停顿、短语保护、段落长度、字符数量和估计换行行数，避免孤立的短尾段。
- 保护常见多词表达、姓名、冠词/介词/助动词/否定词与后续内容。弱边界才请模型批量复核（每组至多 5 个原句），模型只返回整数词位置，不能提供替换英文。
- 模型输入为带明确位置编号的词，切点必须满足顺序、4–24 词、短语保护、不过度增高/碎片化等检查；无效输出或请求失败安全回退到规则切分。接口不可用即停止后续复核，连续两批格式错误也停止，避免无标点长文反复等待超时。英文仅从原文截取，非空白字符完全不变。
- 排版估计依据现有 17sp 单词卡与 360dp 手机的约 294dp 正文宽度，优先控制为约 4 行。它不是设备实测，不保证所有屏幕和系统大字号都能一屏容纳；真正按设备自适应仍需安卓更新。
- 元信息合句不再在 320 字符处直接输出，保留较完整的原句上下文；极长无标点缓冲仍设 2400 字符安全阈值。每篇最多 600 个原始句子、2000 个阅读片段、12 万英文字符。

## 双语与原句

先确定英文片段，再批量翻译，短阅读片段每组最多20个，普通完整短句仍为10个。每组译文输入包含当前片段、完整原句和相邻英文；模型只翻译当前片段，保持前后衔接，不把整句翻译重复到每个片段里。旧中文不机械切割：只重译发生分段的原句，未切短句及已完成片段保留原译文。翻译失败只重试未完成片段，不重新下载字幕或反复规划切点。

现有 `sentences` 数组直接返回短片段，保留 `id/time/english/chinese/translationStatus`，旧 Web/Android 可读取。没有另设旧客户端不能识别的显示数组。

- 第一片段保留原句 ID；后续片段使用基于起始词位置的稳定 ID，避开已有编号。
- 第一片段额外保存 `sourceSentence` 完整原文、旧译文与时间，后续通过 `sourceSentenceId` 引用，不在每个片段重复整句数据。
- `readingVersion` 标记已完成规划，重试保持片段编号不变。新版规划可从原句恢复；改变切点前保存旧片段 ID 别名，旧草稿仍能解析为完整原句，未改动的英文片段保留原译文。
- 收藏来源由服务器解析到完整原句，旧草稿和新片段均可使用；原有来源快照、笔记和复习记录不修改。
- 目前没有词级时间戳，因此片段沿用原句时间，不按词数伪造精确的音频定位。

以上元数据均存于现有 JSONB，不需要数据库结构迁移。

## 已有文章更新与客户端缓存

`scripts/ops/upgrade-reading-segments.ts` 默认只读预览，备份数据库后使用 `--apply` 为需要分段的已有文章重新排入后台。沿用已保存英文和原有文档任务，不重新访问 YouTube，也不重复创建历史文档。再次执行不会为已完成分段的文章排队。

重新选择已有视频时，服务端也会检查是否需要更新。旧 APK 从学习记录优先打开本机正文，仅刷新历史摘要或重启不会刷新已完成正文；要从“查找”重新选择同一视频，才能获取新版。不要清除应用数据，避免丢失未提交草稿。内置离线文章优先使用 APK 资源，不由本次服务器更新替换。

回退代码后，新短片段仍有旧格式字段，文章可以继续读取。原句保存在元数据中，不应为回退而恢复整个数据库覆盖新的学习数据。
